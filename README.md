# ナゾトキマーケット2026 買い物メモ（非公式）

ナゾトキマーケット2026（2026-11-07 土・11-08 日、東京ドームシティ プリズムホール）で何を買うかを決めるための、非公式の Web ツールです。

**非公式です。** 主催・出展団体とは関係ありません。商品・価格は公式サイトと各団体の告知（X・HP）で確かめられたものだけを載せ、出典の URL と取得日を商品ごとに残しています。最新の正確な情報は公式サイトと各団体の告知で確かめてください。団体のロゴや商品画像はこのリポジトリに保存せず、元のサイトの URL を参照して表示しています。X に投稿された画像は、公開ページを作るときに取得して同梱しています。出典の投稿は各商品の詳細に載せています。商品画像の権利は各団体・主催に帰属します。

## できること

| タブ | 内容 |
|---|---|
| 一覧 | 価格・難易度・カテゴリ・出展日・タグ・キーワードで絞り込み、ブース順・団体順・価格順・難易度順などで並べ替え。おすすめ順はリスト内の商品の傾向や、手動で設定した好み・予算を使い、最大10件を表示する。推定の難易度には「推定」と出す |
| リスト | 商品の数量、合計と予算を確認し、買えた商品に印を付ける。購入済みの商品の数量を変えるには、先に購入チェックを外す。使った金額・使える残り・購入点数を表示する。価格不明の件数は別に数え、リストをテキストでコピーできる |
| マップ | 未購入の商品があるブースを色付けし、すべて買えたら色を消す。選択したブースでは、リストに入れた商品に購入チェックを付けられる。未購入の団体一覧や番号・出展者名からブースを選べる |

一覧では出展日を「すべて／土曜／日曜」から選べます。マップの日付はマップ内で選び、土日で入れ替わる出展者を表示します。個人リストや画面の設定はブラウザ（localStorage）に保存されます。

### 共同リスト

リスト画面の「共同リストを作成」で空の共有リストを作れます。「今のリストをコピーして共同リストを作成」では、個人リストの商品・数量・購入状況・予算を新しい共有リストへ移します。コピー中に通信が切れた場合や毎分120回の書き込み上限に達した場合は、画面の進捗と再試行の案内を確認してください。作成後は「共有リンクをコピー」からメンバーや自分の別端末にリンクを送れます。リンクを開いた人は、商品・数量・購入状況・予算を共同で編集できます。**リンクを知っている人は編集できるため、参加する人だけに送ってください。** 個人リストは別に保存され、「個人リストに戻る」で切り替えられます。共同リストの内容は同期のためCloudflareに保存されます。

共同リストを開いたまま一覧やマップを再読み込みしても、その画面を表示したまま接続します。ヘッダーには同期状態が表示され、押すとリスト画面へ移れます。閉じたタブに未送信操作が残っている場合、次に開いたタブはそのタブのロックが空いていれば操作を引き継ぎます。画面を非表示にしている間は定期同期を止め、戻るとすぐ同期します。

通信が切れたときや同時編集が重なったときは、画面に表示される案内を確認してください。無料枠の上限に達すると、一時的に同期できなくなる場合があります。

## 動かし方

Node.js 24 以上が必要です。

```bash
npm install
```

```bash
npm run dev
```

表示された URL（例 `http://localhost:5173/`）をブラウザで開きます。

ほかのコマンド:

| コマンド | 内容 |
|---|---|
| `npm test` | テスト（ロジック・データの検証・データ組み立てスクリプト） |
| `npm run typecheck` | 型チェック |
| `npm run build` | `dist/` に静的ファイルを書き出す（相対パスなので、どこに置いても開ける） |
| `npm run preview` | 書き出したものをローカルで確認 |

## 公式データを取り直して反映する

公式の出展者・商品データは更新されることがあります。取り直すときは次の順に進めます。生成先に手元の変更がある場合は、先に内容を確認してください。

1. 公式データを取得する。日本時間の当日の日付を使い、`data/raw/YYYY-MM-DD/` に TSV の原本、取得日時とマップ画像のハッシュを記録した `meta.json`、差分 `diff.md` を保存します。同じ日に再実行すると、その日のファイルは上書きされます

   ```bash
   npm run fetch-official
   ```

2. `data/raw/YYYY-MM-DD/diff.md` で団体と商品の増減・変更を確認します。比較対象は今回より前の最新日付の取得結果です。前回のデータがない場合や、マップ画像のハッシュを比較できない場合も表示されます

3. 差分に応じて必要な入力を直します。公式 TSV に加えて手元の収集結果も組み立て時に使うため、追記や上書き内容が最新情報と矛盾しないか確認します
   - 団体が増えた・ブースが変わった: `data/venue-layout.json`（マップが変わったとき）や `data/booth-code-overrides.json`（名前が自動で対応しないとき）
   - 公式以外の情報（X・HP で見つけた商品や追記）を足す・直す: `data/shards/*.json`

4. データを組み立て直して検証します。`data/raw/` の日付が最も新しい取得結果を使い、`booths.json`・`products.json`・`candidates.json`・`COVERAGE.md` を上書きします。団体とブースが対応しない場合は書き出さずに止まり、理由を表示します

   ```bash
   npm run build-data
   ```

   ```bash
   npm test
   ```

5. `data/COVERAGE.md` で収集のカバー率を確かめ、`npm run build` で書き出します

データの形と値のルール（「推定」の付け方、取れなかった値の扱いなど）は [data/README.md](data/README.md) にあります。

## 作り

- Vite + TypeScript（フレームワークなし）。地図は SVG を自前で描いています
- データ（`data/*.json`）はビルド時に取り込むので、サーバーもログインも要りません
- 公式データの取得は `scripts/fetch-official.ts`、データの組み立ては `scripts/build-data.ts`。取得するのは公式の TSV 2つとマップ画像（ハッシュ値の比較だけ）の3つで、間は1秒あけます
- X の画像の取得は `scripts/fetch-images.ts`。GitHub Pages に公開するときだけ実行し、`public/remote-images/` に置く（git には入れない）。手元で画像を見るときは `node scripts/fetch-images.ts` を一度実行する。間は1秒あける
