# 回る順番の通路対応・一覧への「好みで探す」統合・団体名中心の表示

## 目的

- 回る順番が、会場の通路を歩ける順番と道筋で出る
- 好みに合う商品を、一覧の中で探せる（おすすめタブは無くす）
- ブース番号より団体名で見分けられる

## 1. 回る順番を通路沿いにする

### 今の問題

ブースの中心どうしの直線距離で最近傍法を回し、線も中心どうしを直線で結んでいる。線がブースや壁を突っ切り、A1 → Ba3 → A3 のように通路をまたいで行き来する。

### 方針: 歩ける場所の格子で最短経路を取る

通路を手で計測したグラフは持たない。今ある会場データから歩ける場所を作る。

- 歩ける場所 = `walkway` の多角形の内側 − ブースの矩形 − 目印（協賛・宅配・トイレ）の矩形
- 4px の格子にする（1520×580 → 約 380×145 = 5.5 万マス）。障害物は 4px 膨らませ、線がブースの角に触れないようにする
- 格子: 原点は `viewBox` の左上。マスの中心点が歩ける場所の中にあれば歩ける。移動は縦横が 1、斜めが √2。斜めに進むときは、隣り合う縦横の2マスがどちらも歩けるときだけ通す（障害物の角をすり抜けない）
- 入口・出口が障害物の中や格子の外に落ちたときは、一番近い歩けるマスに寄せる。立ち寄り点が見つからないブース（周りがすべて障害物）は、今の「場所が未定」と同じ区分に入れて線を引かない
- ブースの「立ち寄り点」= 膨らませた後の格子で歩けるマスのうち、ブースの矩形に一番近い1マス（同じ距離なら y の小さい方、次に x の大きい方）。着くのも出るのもこの1点なので、区間をつなぐと必ず一続きの道になる。地図では立ち寄り点からブースの辺の一番近い点まで短い補助線を引く（補助線は自分のブースへの当たり判定から外す。膨らませた幅の中なのでほかの障害物とは交わらない）
- つながり: 入口から歩いて届くマスの集まりだけを使う。立ち寄り点が入口から届かないブースは「場所が未定」と同じ区分に入れて順番と線から外す。出口に届かないときは最後のブースで線を終える。実データでは 94 ブースすべてが入口から届くことをテストで確かめる
- 距離: 8 近傍の格子上の最短距離。入口・各ブース・出口から 1 回ずつ探索して距離表を作る（止まる所が n か所なら n+2 回）
- 順番: 入口から出発し、出口で終わる開いた経路。最近傍法で作り、2-opt で交差をほどく（出口は固定の終点）。「新作・限定を先に」は今どおり、印のあるブースの組を先に回ってから残りを回る
- 返す型: `planWalkingRoute(...)` は `{ stops: { boothId, code, visitPoint }[], legs: Point[][] }`。`legs[i]` は i 番目の区間（入口→1 件目、…、最後→出口）の点列で、各区間の端は立ち寄り点（と入口・出口）にぴったり一致する。地図は `legs` を描き、番号札はブースの矩形の中に出す
- 2-opt は入口と出口を固定し、「新作・限定を先に」のときは印のあるブースの組と残りの組それぞれの中だけで入れ替える
- 再利用: 格子は1回だけ作る。各立ち寄り点からの探索結果（距離と親）を立ち寄り点ごとにメモし、リストに入るブースが増減したときだけ新しい点を探索する。数量の変更や「新作・限定を先に」の切り替えでは探索しない（地図側は、ブースの集合と設定が同じなら再計算しない）
- 線: 格子上の経路を、見通しが利く点まで飛ばして単純化する（string pulling）。単純化した線分も障害物を横切らないことを確かめる
- 計算はリスト・行く日・設定が変わったときだけ。格子は初回に1回作って使い回す

### 判断ログ

- 通路の幅: 公式マップでブースのかたまりの間は 15px ほどしか空いていない（列と列の間の通路は 35〜40px）。かたまりの間も通れる通路として扱う（4px 膨らませても 7px 残る）。会場で通れなかった場合はかたまりの間を障害物にする設定で直せるようにする
- 出口を終点に入れる: 入口（右下）から入って出口（左）から出る会場なので、出口に向かって進む順の方が歩く距離が短く現実に合う
- 手で通路グラフを作らない: 計測の手間と、マップ更新時の作り直しを避ける

### テスト

- 線分が、どのブース・目印の矩形とも交わらない（全ブースを1件ずつ入れた場合と、全部入れた場合）
- 入口 → Ca10 の経路の長さが、直線距離より長い（ブースのかたまりを回り込む）
- 隣どうしで通路をはさむ A1・Ba1・A3・Ba3 を入れたとき、通路をまたいで往復しない（順番の合計距離が、今の直線版の順番より短いか等しい）
- 出口が最後になる。止まる所が 0 件なら線を描かない
- 区間の端が立ち寄り点・入口・出口でつながっている（`legs[i]` の終点 = `legs[i+1]` の始点）
- 細い通路（かたまりの間の 15px）を通る経路が作れる
- 「新作・限定を先に」で、2-opt の後も印のあるブースが先に並ぶ
- 数量を変えても探索の回数が増えない（探索回数を数える）
- 性能: 20 か所で 1 回の計算が 50ms 以内（Node で測る）

## 2. おすすめタブを無くし、一覧に「好みで探す」を入れる

- タブは「一覧／リスト／マップ」の3つ。古い保存や `#insights` は一覧で開く
- 一覧の絞り込み欄（PC は左の欄、スマホはシート）の先頭に「好みで探す」を置く: 予算（初期値はリストの残り予算、「残り予算を使う」ボタン）、難易度の下限・上限、好きなカテゴリ、遊び方。今のおすすめタブの入力と保存項目（`prefs`）をそのまま使う
- 並び順に「おすすめ順」を足す。好みを1つでも変えたら並び順をおすすめ順にする
- おすすめ順のとき: 点数の高い順。予算超えと行く日に売っていない商品は除く（今の `recommend` と同じ）。点数が 0 以下の商品は「条件に合う商品」の後ろに「ほかの商品」として続ける。カードには理由（「予算内」「好みの難易度」など）だけを出し、点数は出さない
- 点数の付け方の表、価格・カテゴリの分布図、エリアの地図は画面から外す（点数の付け方は `insights.ts` の中にだけ持つ）
- リストに入っている商品も除かない（1ボタンで外せるようにするため）
- 予算の判定: 「予算 −（その商品以外のリストの合計）」をマイナスも含めて計算し、その商品の小計（価格 × リストの数量、リストに無ければ × 1）と比べる。合計には買えた商品も含める（予算は使う予定の総額なので）。価格不明の商品は合計に入れず、採点もしない（今どおり）。テスト: ほかの商品だけで予算超過のとき・数量 2 以上・価格不明
- 採点の関数は `scoreProduct(view, prefs, budgetLeftForThis)` のように、その商品にとっての残り予算を受け取る形にする
- 一覧用の結果: `rankForCatalog(catalog, prefs, items)` が `{ matched: Scored[], others: ProductView[] }` を返す（matched は点数 1 以上を点数順、others はそれ以外をブース順。予算超え・行く日に売っていない商品は others にも入れない）
- 更新のきっかけ: 並び順がおすすめ順のとき、`prefs`・行く日・リストの商品と数量が変わったら並べ直す。予算の入力は確定（change）時に反映する（入力の1文字ごとには並べ直さない）
- 旧リンク: `#insights` と保存済みの `tab: "insights"` は一覧で開き、並び順をおすすめ順にする

## 3. 団体順と折りたたみ

- 並び順に「団体順」を足す（団体名の五十音順。`Intl.Collator("ja")`）
- 「ブース順」「団体順」のときは、団体ごとに見出し（団体名・ブース番号・件数）を付けて `<details open>` でまとめ、見出しを押すと折りたためる。「すべて閉じる／すべて開く」ボタンを並び順の横に置く
- 開閉の状態は保存しない（並び順や絞り込みを変えると全部開く）
- 性能: 開閉でカードを作り直さない。並び順・絞り込み・おすすめ順の並べ直しでも、商品IDごとにカードを使い回し、DOM の位置を動かすだけにする（今の `catalogView` は同期のたびにカードを作り直しているので、ここで直す）。テストでは並べ直しの前後でカード要素が同じであることを確かめる

## 4. 団体名を主にする

- 商品カード: 本文の先頭に団体名（太字）。半券のブース番号は小さくし、「ブース」の文字の下に添える
- リストの回る順番の見出し: 「1. 団体名」、ブース番号は後ろに小さく
- マップの回る順番の一覧も同じ。地図の上のブースの文字は、場所が狭いので今どおり（ブースを押したときのパネルは団体名を大きく）

## 5. 見た目の手直し

- 合計金額をひと目で分かるようにする: 画面下の予算帯で「合計」を大きく（数字を 20px 以上・太字）、予算があれば「残り／超過」をその横に。スマホでも1行目に合計が来る
- タブ: 左に詰めて並べるのをやめ、スマホは下の帯で3つを等幅に、PC は上の帯で中央にそろえる。今いるタブがひと目で分かる形（下線か背景）にする
- 商品カードの左の半券: ブース番号ではなく団体名を出す（長い名前は2行まで折り返して省略、ブース番号はその下に小さく）
- 画像が見切れる: カードの画像は切り抜かず（`object-fit: contain`）、余白は地の色で埋める。縦長・横長どちらでも全体が見える
- 全体の見た目を整える: 一覧・リスト・マップで余白・見出し・箱の重なり（箱の中の箱）をそろえる。具体は実装時に `frontend-design-fix-sync` で上位3〜5件に絞る

## 行く日の判定（今の仕組み。変更なし）

画面上の「土 11/7／日 11/8」は利用者が選ぶ。商品・団体がその日に出るかは、公式の出展者リスト（booth.tsv の「両日出展／土曜出展／日曜出展」）から団体ごとに決め、商品は団体の出展日を引き継ぐ。会場マップは土日でブースの団体が入れ替わる3か所（Cc6・Cc7・Ce5）を別に持つ。

## 範囲外

- 足りない商品情報の集め直し（イベント1週間前の 10/31 ごろに行う）
