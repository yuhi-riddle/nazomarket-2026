# 実装計画: 回る順番の通路対応・一覧への「好みで探す」統合

設計: `docs/design-route-and-catalog.md`

機能ごとに「失敗するテストを用意 → 実装 → テスト・型・ビルド・画面確認 → コミット」で進める。

## 1. 通路沿いの回る順番（設計 1）

- 新しい `src/logic/walkingRoute.ts`: 格子づくり・立ち寄り点・距離表・順番（最近傍法＋2-opt、入口と出口を固定）・線の単純化
- テスト `src/logic/walkingRoute.test.ts`（実データの会場で）: 全ブースに届く・線が障害物を横切らない・区間がつながる・通路をまたいで往復しない・新作限定を先に・探索の使い回し・性能
- 地図（`mapView.ts`・`venueMap.ts`）とリストの回る順番（`cartView.ts`）を新しい順番と線に切り替える。補助線はブースの辺まで
- 今の `planRoute`（直線の最近傍法）は使わなくなったら消す

## 2. 一覧に「好みで探す」・おすすめ順・団体順（設計 2・3）

- `insights.ts`: その商品にとっての残り予算で採点、`rankForCatalog`
- `catalog.ts`: 並び順に `recommended`・`organization`
- 絞り込み欄の先頭に「好みで探す」、おすすめタブと分布図・点数表・エリア地図を削除、`#insights` と保存値の移行
- 一覧のカードを商品IDで使い回し、ブース順・団体順は団体ごとの `<details>`
- 画面の確認スクリプト `work/scripts/qa_catalog_prefs.py` を先に書いて RED を確かめる

## 3. 見た目の手直しと団体名中心の表示（設計 4・5）

- 予算帯の合計を大きく、タブを等幅・中央に、半券に団体名、画像を切り抜かない
- リスト・マップの回る順番の見出しを「団体名＋小さいブース番号」に
- 画面の確認スクリプトに、合計の文字の大きさ・タブの幅・画像が切れていないこと（`object-fit`）を足す
