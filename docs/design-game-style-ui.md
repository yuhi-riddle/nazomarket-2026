# 見た目の刷新（濃紺と金・押したときの手応え・GET! 演出）

## 目的

- 下調べと当日の買い回りが、少しゲームのように楽しく感じられる
- 押したときの手応えと、買えたときの「GET!」で達成感が出る
- マップは一覧とリストの補助として、ブースの場所で迷わないようにする

機能とデータは変えない。画面の見本は Design キャンバス「謎マーケット UI ゲーム風リデザイン」（一覧・アイテム詳細・アイテムリスト・マップ）。

## 1. 配色と書体

- 濃い紺を地にした1系統にする。`:root` を `color-scheme: dark` にし、`prefers-color-scheme: dark` の上書き（`styles.css` 56行付近）は消す。3219行付近の後段ルールにある経路と経路マーカーの金色は、基本のルールへ移してから消す。`index.html` の `theme-color` は両方 `#0b0e1c`
- トークン（`:root` に追加・置き換え）

| 役割 | 値 |
|---|---|
| 地 `--bg` | #12162a |
| 面 `--surface` / `--surface-2` | #1c2240 / #262d52 |
| 帯 `--band` | #0b0e1c |
| 線 `--line` | #2a3260 |
| 文字 `--ink` / `--ink-muted` | #eef0fa / #a9b0cf |

- 書体: 見出し・タブ・価格・金額・ブース番号だけ DotGothic16。`--font-pixel: "DotGothic16", <今の本文書体>`。`index.html` で Google Fonts を `display=swap` で読む。読めないとき（オフラインなど）は本文書体で表示される

## 2. 文言

- 画面に出る「商品」は「アイテム」にそろえる（アイテム詳細・アイテムリスト・アイテム 124件・読み上げ用のラベルを含む）
- ほかの言い換え（クエスト・所持金・ステータスなど）はしない

## 3. 一覧とアイテム詳細

- カードの枠を難易度で色分けする。`productCard.ts` でカードに `data-difficulty="1"〜"5" | "unknown"` を付け、CSS で枠を決める。後段の `border: 0`（`styles.css` 2655行付近）が幅と種類も消すので、`border` 自体（2px・実線、不明は破線）を後から定義し直す
- 難易度の値から属性値を出す処理は純粋関数 `difficultyTier(level)` にする（1〜5 以外と null は `unknown`）
- 色だけに頼らない。星表示と「推定」タグはそのまま残す
- アイテム詳細の団体名の横に「地図で場所を見る」を置く（6章）

## 4. 予算ゲージと押したときの動き

- 予算メーターの見た目を金色のゲージにする（構造と計算は今のまま）。幅の変化は今の transition を少し弾む曲線にする
- 「リストに入れる」で追加したとき、ゲージの近くに「+¥金額」を浮かべて消す。呼ぶのは `productCard.ts` の追加ボタンの `click` だけで、押す前にリストに無く、価格が分かっているときに限る。外したときと store の通知（共同リストの同期を含む）では出さない。装飾なので `aria-hidden`
- 金色のボタン（主操作）は押すと 3px 沈み、下の影が消える。カードとリストの行は押すと 0.97 倍に縮む
- 動きは今の `prefers-reduced-motion: no-preference` のブロック（`styles.css` 2034行・2906行付近）に足す

## 5. GET! 演出

- `src/ui/gameFx.ts` に `celebrateGet(itemName)` と `floatGain(text)` を置く
- 呼ぶ場所: アイテムリストの購入チェック（`cartView.ts`）と、マップのパネルの購入チェック（`productCard.ts` の `onToggleBought`）の `change` で、チェックが付いたときだけ。store の通知からは呼ばない（共同リストの同期で他の人の操作が届いたときに出さないため）
- 表示: 画面中央に「GET!」とアイテム名の札が飛び出し、四角い火花が散って約1.3秒で消える。`pointer-events: none`。要素は body に1つだけ作って使い回し、続けて出すときはアニメーションを最初からやり直す
- 消すタイミングは `setTimeout(1300)` で決める（動きを減らす設定ではアニメーションが 0.01ms で終わるので、`animationend` には頼らない）。続けて出すときは前のタイマーを `clearTimeout` してから張り直す
- 読み上げ: 常に置いてある `aria-live="polite"` の領域に「〇〇を購入済みにしました」を入れる。札は `aria-hidden`
- 購入済みの行に「GET!」の印を付ける。リストの進み具合は「GETした数 n / m」

## 6. マップ

マップは一覧とリストの補助として、「そのブースがどこにあるか」で迷わないためのものにする。演出（光・跳ねる印・道順の線）は入れない。

- ブースの位置・大きさ・通路・目印は `data/venue-layout.json` のまま
- ブースの状態を分ける純粋関数 `boothListStatus(...)` を `src/logic/mapBooths.ts` に置く
  - `todo`: その日にリストのアイテムがあり、未購入が1件以上
  - `clear`: その日にリストのアイテムがあり、全部購入済み
  - なし: リストのアイテムがない
- ブースの `g` に `data-list-status="todo" | "clear"` を付ける。`todo` は金色、`clear` は緑の枠と暗い緑の塗り、なしは落ち着いた紺。団体名の表示は今のまま
- `todo` のブースに未購入の点数のバッジを出す。地図の倍率に合わせて描き直し、画面上の大きさを一定に保つ。全体表示（倍率が低いとき）は数字なしの点にし、拡大したら数字を出す。スマホ幅の全体表示では小さいブースが約9pxになり、数字のバッジが隣のブースを隠すため。バッジの層は `aria-hidden`
- 読み上げ: ブースのアクセシブル名に状態を入れる（「未購入N点」「全部購入済み」）。リストのアイテムが無いブースは今のまま
- ブースを選ぶと、今の「選択したブースの商品」パネル1つに出す。並びは、リストのアイテム（購入チェック付き）→ ほかの販売アイテム（「リストに入れる」付き）。アイテム名で詳細が開く。リストのアイテムが無いブースでも販売アイテムは出す。地図を押したらパネルへ移る今の処理（`mapView.ts` 138行付近）は残す
- 一覧・リストから地図へ: アイテム詳細とアイテムリストの行に「地図で場所を見る」を置く。押すとマップタブを開き、そのブースを選んだ状態にして、地図をそのブースが見える位置へスクロールする
- 最初の表示範囲は、予定のあるブースが収まる範囲。決めるのはタブを開いたときの1回だけで、買い進めても動かさない。「会場全体」で全体へ
- 拡大縮小・選択・再描画の仕組みは変えない。「描画内容が同じブースは飛ばす」仕組み（`venueMap.ts` の paintKey）に状態を含め、バッジは状態か倍率が変わったときだけ更新する。SVG 全体は作り直さない
- 性能の合格基準: 1280px・headless・各操作10回で、通常 CPU の土日切替・拡大縮小・ブース選択・購入チェックに 50ms 超のフレームが無いこと。CPU 4倍遅の地図タブ初回表示の最大値が 186ms（これまでの最大値 155ms の 1.2 倍）以下であること

## 7. 動きを減らす設定

- `prefers-reduced-motion: reduce` では、沈む・縮む・火花・浮かぶ金額・ゲージの弾みをすべて止める
- GET! の札は動かさずに1.3秒だけ出す。読み上げは同じ

## 8. テスト

- vitest は DOM 環境を持たないので、DOM 操作のテストは足さない
- 純粋関数 `difficultyTier`・`boothListStatus` はテストを先に書く
- 演出と見た目は visual-qa で実ブラウザ（PC 幅・スマホ幅）で確かめる。性能は6章の基準で測る

## 判断ログ

| 何を決めたか | なぜ |
|---|---|
| ライト／ダークの2系統をやめ、濃い紺の1系統にする | 濃い地でこそ金と光の演出が映える。明るい版を別に持つと保守する色が倍になる |
| DotGothic16 は Google Fonts から読み、自前で持たない | ライブラリを足さない方針。オフライン対応はまだ無く、読めなくても本文書体で崩れない |
| GET! は購入チェックの `change` からだけ出す | store の通知には更新元が無く、共同リストの同期でも状態が変わるため、差分から出すと誤って出る |
| マップは補助にとどめ、演出を入れない | 主に使うのは一覧とリスト。マップは場所の確認に絞ったほうが、会場で見たときに分かりやすい |
| 行き先の一覧は作らず、選んだブースの中身はパネル1つに出す | リストタブと役割が重なる。同じ中身を2か所に描くと購入チェックの同期とフォーカスの戻し先が増える |
| 全部購入済みのブースでも団体名は残す | 名前で場所を覚えている人が見失わないようにする |
| 画面の「商品」を「アイテム」にそろえ、ほかの言い換えはしない | 見出し同士の統一感を出しつつ、意味の分かりにくい言葉は増やさない |
| リストのアイテムが無いブースの読み上げは今のまま | 読み上げ文の変更を、新しく区別できるようになった「全部購入済み」に絞る |
